# Design

## Context

动机见 `proposal.md`，学生可见的行为要求见 `specs/course-catalog/spec.md`。当前检出的目标分支是 `lecture`。来源分支为 `SuperMimic`、`SuperMimicPoleWeave` 和 `MAPPO4V4`；本地 Git 检查显示，`lecture` 与前两个分支没有共同合并基点，而 `MAPPO4V4` 与目标分支有共同历史。`SuperMimicPoleWeave` 基于 `SuperMimic` 继续开发。

来源项目在根目录包含不少重叠文件，例如 README、依赖清单、训练和回放入口，以及机器人和仿真资源。各分支的忽略规则也不相同。最终目录需要让每门课程的算法代码易于修改，同时避免重复维护通用机器人和仿真基础设施。

## Goals / Non-Goals

**Goals:**

- 将三个来源分支整合到当前目标分支并保留 Git 历史，以支持后续常规合并。
- 为每门课程设置面向学生、按任务命名的目录和文档入口。
- 共享稳定的机器人资源、仿真代码和通用工具，同时保持课程算法与任务逻辑相互独立。
- 整合目标分支和来源分支的忽略规则，避免忽略构建、训练或演示所需的资源文件。
- 让根目录 README 成为简明入口，分别引导初次演示和实验复现。

**Non-Goals:**

- 重写或比较现有基线使用的算法。
- 保证完整规模训练的性能或模型质量。
- 在本次变更中修改上游来源分支。
- 在整合后删除来源分支。

## Decisions

### 通过合并提交保留分支历史

将来源分支合并到当前目标分支并保留提交历史。`SuperMimic` 与 `lecture` 没有共同合并基点，因此首次合并时需要允许合并无关历史。先合并 `SuperMimic`，再合并基于它开发的 `SuperMimicPoleWeave`，之后利用现有共同历史合并 `MAPPO4V4`。每个来源分支单独生成合并提交，以便隔离冲突并在需要时分别回退。

由于来源分支预计会继续迭代，本方案优于导入代码快照。保留历史可以让后续合并聚焦于尚未整合的新提交，但不能消除冲突：初次整合时根目录文件会冲突，文件内容有重叠修改时会冲突，目录重组后路径变化也可能造成冲突。子树导入可以隔离路径，但不便于后续按来源分支整体同步。

### 按任务组织课程，只共享稳定基础设施

建立 `courses/football-kicking/`、`courses/pole-weaving/` 和 `courses/soccer-4v4/` 三个任务目录，分别维护课程介绍、快速开始指南、配置以及训练/演示入口。绕杆课程依赖踢球分支使用的 SuperMimic 框架和专家策略，因此将 `q1_soccer`、`expert` 作为 `shared/supermimic/` 维护；绕杆专属逻辑保留在 `courses/pole-weaving/`。上游 `3rdparty/SuperMimic` 子模块作为共享依赖暂留仓库根。4v4 的 `q1_4v4`、训练与回放脚本、MAPPO 依赖和专属场景资源放在 `courses/soccer-4v4/`。当前通用 `envs/`、`utils/`、动作数据和未归属课程的机器人资源放在 `shared/q1-mujoco/`，不与三门课程的算法包混合。

为兼容现有导入名和测试，迁移后在仓库根保留指向新目录的符号链接；课程文档直接使用课程目录入口。上游 `3rdparty/SuperMimic` 子模块路径暂留仓库根，避免每次同步来源分支时重复处理子模块路径迁移。实施时先检查依赖导入和调用位置；如果两个版本行为不同，在确认兼容前保留各自实现。

### 根据文件清单整合 `.gitignore`

逐一比较目标分支和所有来源分支的 `.gitignore`，将规则归纳为 Python 缓存、训练日志、模型与检查点输出、视频、本地凭据和课程生成文件等类别。保留源资源所需的例外规则，例如 artifacts 目录中的场景图片。不要直接照搬宽泛规则：需针对整个目录的忽略规则检查已跟踪的源码和课程资源。使用 Git 忽略诊断确认规则命中情况，并确认必需文件仍可加入版本控制。

### 根 README 放通用信息，课程页放具体步骤

根目录 README 介绍项目，提供快速演示和实验复现入口，列出三个任务名称并说明通用安装要求。每门课程的页面负责维护详细命令、参数、模型位置、评估说明和基线介绍。来源分支名仅用于维护者追溯，不作为学生看到的课程名称。

### 分课程独立验收

对每门课程运行短程训练冒烟配置，再使用冒烟运行生成的 checkpoint 进行无头演示，运行到固定步数并正常退出；演示不要求模型达到完整训练效果。训练初始化仍可依赖课程说明的外部权重或数据。将命令和成功条件写在对应课程文档中。单门课程出现问题时，应能在不依赖其他课程训练流程的情况下进行诊断。

## Risks / Trade-offs

- [无共同历史且根目录文件重叠] → 每次只合并一个来源分支，为每个来源保留独立合并提交，并根据最终课程目录和共享层设计解决根目录冲突。
- [目录迁移后的后续合并] → 在维护者说明中记录来源分支名和合并提交；同步上游新提交时检查重命名及修改/删除冲突。
- [抽取共享层导致行为变化] → 只共享已确认行为兼容的文件；无法确认的重复实现先留在各课程目录。
- [忽略规则范围过宽而遗漏资源] → 检查必需的机器人模型、动作、配置和演示资源是否被忽略；生成文件与源文件同目录时添加明确例外。
- [课程训练依赖的初始化权重或数据未随 Git 提交] → 在课程页面注明文件用途、获取方式和本地路径；演示验收使用课程冒烟运行生成的 checkpoint。

## Migration Plan

1. 记录各来源分支的提交位置，并确认它们与当前目标分支的历史关系。
2. 首先以允许无关历史的方式合并 `SuperMimic`，然后合并 `SuperMimicPoleWeave` 和 `MAPPO4V4`；分别解决根目录文件冲突并生成独立合并提交。
3. 将导入的课程内容调整到任务目录，只抽取确认可共用的基础设施。
4. 整合 `.gitignore`、根 README、通用安装说明和各课程文档。
5. 执行三门课程的训练冒烟检查，以及所有可用模型的无头演示。
6. 如果发布后需要撤销某次合并，分别回退该合并及依赖它的目录重组提交，不改写已共享的历史。

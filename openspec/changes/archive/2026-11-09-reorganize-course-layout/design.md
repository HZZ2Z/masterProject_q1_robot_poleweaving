# Design

## Context

参见 `proposal.md`。当前课程内容集中在 `courses/`，通用 MuJoCo 代码位于 `shared/q1-mujoco/`，共用 SuperMimic 实现预期位于 `shared/supermimic/`。现有维护清单记载部分根目录路径是兼容入口，但实际文件状态需实施前逐项核实；根目录还存在课程名导入被测试和脚本使用的兼容约束。

## Goals / Non-Goals

**Goals:**

- 用目录位置表达课程专属代码和跨课程共享代码的归属。
- 每个实现只保留一份规范源码；兼容入口不得包含第二份实现。
- 保持现有 Python 导入名、命令入口及课程运行行为。
- 让预期目录结构可直接作为迁移和验收依据。

**Non-Goals:**

- 重命名 Python 包或重写算法。
- 改变训练配置、模型格式、课程能力或运行时行为。
- 把运行产物、日志或模型检查点纳入版本控制。

## Decisions

### 规范目录按课程和共享职责划分

预期结构如下；`[保留]` 表示继续使用现有位置，`[迁入/核实]` 表示实现阶段按 Git 跟踪状态、内容哈希和引用关系确定唯一实现位置。根目录不保留课程源码副本。

```text
.
├── courses/
│   ├── football-kicking/             # 课程说明、配置；训练框架由 shared 提供
│   ├── pole-weaving/
│   │   ├── pole_task/                 # 绕杆任务唯一实现
│   │   └── q1_supermimic/             # 绕杆训练入口/扩展
│   └── soccer-4v4/
│       ├── q1_4v4/                    # 4v4 唯一实现
│       ├── scripts/
│       ├── resources/
│       ├── train.py
│       └── play.py
├── shared/
│   ├── q1-mujoco/                     # 通用仿真、模型、动作数据
│   └── supermimic/
│       ├── q1_soccer/                 # 踢球与绕杆共用训练框架
│       └── expert/                    # 共用专家策略与数据
├── tests/                             # 项目级测试
├── scripts/                           # 仓库级工具及指向课程脚本的兼容链接
├── docs/
└── README.md
```

`q1_soccer`、`q1_supermimic`、`q1_4v4` 根路径当前都是指向上述规范目录的 Git 符号链接，不是重复源码，保留以兼容现有导入。`q1_slalom` 只有被忽略的 Python 缓存，无受跟踪源码或引用，清理缓存即可。无需迁移这些包的实现；本次只维护规范布局、兼容入口和文档一致性。

### 兼容性优先使用非复制入口

迁移后更新测试、脚本和文档指向规范路径。确有外部或已有仓库入口依赖时，保留根目录符号链接或薄包装；选择前验证 Windows/容器及 Python 包解析场景。相比保留两份源码，这能让旧入口继续工作而不引入同步负担；相比立即改包名，风险较低。

### 保留项目级测试与共享资产边界

`tests/` 继续作为统一测试入口。通用 Q1/G1/T1 环境和动作数据归 `shared/q1-mujoco/`；课程专属场景、配置和训练脚本归各自课程。相同哈希资产只保留一个规范副本，课程专属资产不合并。

## Risks / Trade-offs

- [路径迁移遗漏动态拼接或文档命令] → 迁移前全仓搜索旧路径，迁移后检查导入、脚本路径和课程 README。
- [符号链接在某些打包或 Windows 场景失效] → 优先评估薄包装适配性，并记录支持范围；不复制业务实现。
- [共享包边界判断错误] → 以导入图和职责核对 `q1_soccer`；只有跨课程通用部分放入共享目录。
- [Git 中记录与工作区观察不一致] → 以 `git ls-files`、`git status`、历史和文件哈希为依据，避免覆盖用户本地状态。

## Migration Plan

1. 记录 Git 跟踪状态、规范目录、根目录符号链接及源码引用，确认没有重复实现。
2. 清除无引用的 `q1_slalom` 缓存目录。
3. 按当前规范结构更新维护清单和根 README；只有发现真实失效引用时才修改对应路径。
4. 检查符号链接目标、Python 导入和文档命令；若发现失效入口，修正链接而不复制源码。
5. 若验证失败，恢复对应链接并修复映射；保留工作区中与本变更无关的改动。
